# Optimism Bedrock 主要流程时序图

## 综合时序图（存款、提款、争议）

```mermaid
sequenceDiagram
    participant User as 用户
    participant L1Bridge as L1StandardBridge
    participant L1Messenger as L1CrossDomainMessenger
    participant Portal as OptimismPortal2
    participant RollupNode as Rollup节点
    participant Sequencer as Sequencer
    participant L2Messenger as L2CrossDomainMessenger
    participant L2Bridge as L2StandardBridge
    participant L2ToL1Passer as L2ToL1MessagePasser
    participant Prover as 证明者
    participant Challenger as 挑战者
    participant Factory as DisputeGameFactory
    participant Game as FaultDisputeGame
    participant AnchorRegistry as AnchorStateRegistry
    participant MIPS64 as MIPS64虚拟机

    Note over User,MIPS64: ========== 流程1: 存款流程 ==========
    rect rgb(200, 230, 255)
        User->>L1Bridge: depositETH(amount, gasLimit, extraData)
        L1Bridge->>L1Messenger: sendMessage{value: amount}(L2Bridge, finalizeBridgeETH)
        L1Messenger->>Portal: depositTransaction(to, value, gasLimit, false, data)
        Portal-->>RollupNode: TransactionDeposited 事件
        Note over RollupNode: 监听事件，构建L2区块
        RollupNode->>Sequencer: 提交L2区块（包含存款交易）
        Sequencer->>Sequencer: 计算新的状态根
        Sequencer->>AnchorRegistry: 提议新的输出根
        RollupNode->>L2Messenger: 执行存款交易
        L2Messenger->>L2Bridge: finalizeBridgeETH(from, to, amount, extraData)
        L2Bridge->>User: 转账 ETH
        L2Bridge-->>User: ETHBridgeFinalized 事件
    end

    Note over User,MIPS64: ========== 流程2: 提款流程 ==========
    rect rgb(255, 230, 200)
        Note over User,L2ToL1Passer: 阶段1: L2发起提款
        User->>L2Bridge: withdraw(l2Token, amount, gasLimit, extraData)
        L2Bridge->>L2Messenger: sendMessage{value: amount}(L1Bridge, finalizeBridgeETH)
        L2Messenger->>L2ToL1Passer: initiateWithdrawal(target, gasLimit, data)
        L2ToL1Passer->>L2ToL1Passer: sentMessages[withdrawalHash] = true
        L2ToL1Passer-->>RollupNode: MessagePassed 事件
        Note over RollupNode: 将L2ToL1MessagePasser的存储根包含在输出根中
        RollupNode->>Sequencer: 提交包含提款的L2区块
        Sequencer->>Sequencer: 计算新的状态根（包含提款）
        Sequencer->>AnchorRegistry: 提议新的输出根

        Note over User,L2ToL1Passer: 阶段2: L1证明提款（等待挑战期）
        Note over Portal: 等待挑战期（通常7天）
        Prover->>Portal: proveWithdrawalTransaction(tx, disputeGameIndex, outputRootProof, withdrawalProof)
        Note over Portal: 验证Merkle证明<br/>验证输出根证明<br/>检查DisputeGame状态
        Portal->>Portal: provenWithdrawals[withdrawalHash][prover] = ProvenWithdrawal
        Portal-->>Prover: WithdrawalProven 事件
        Note over Portal: 等待 PROOF_MATURITY_DELAY_SECONDS

        Note over User,L2ToL1Passer: 阶段3: 最终确认提款
        User->>Portal: finalizeWithdrawalTransaction(tx, proofSubmitter)
        Portal->>Portal: 检查证明成熟度<br/>检查DisputeGame有效性
        Portal->>Portal: finalizedWithdrawals[withdrawalHash] = true
        Portal->>L1Bridge: finalizeBridgeETH (通过SafeCall)
        L1Bridge->>User: 转账资产
        Portal-->>User: WithdrawalFinalized 事件
    end

    Note over User,MIPS64: ========== 流程3: 争议流程（如果状态根无效）==========
    rect rgb(255, 200, 200)
        Note over Challenger,MIPS64: 阶段1: 创建争议游戏
        Challenger->>Factory: create(gameType, rootClaim, extraData)
        Note over Challenger: 发现Sequencer提交了无效的状态根
        Factory->>Game: initialize() {value: initBond}
        Game->>AnchorRegistry: 获取锚定根
        Game->>Game: claimData.push(rootClaim)
        Game->>Game: 存入保证金到WETH
        Game-->>Challenger: GameCreated 事件

        Note over Challenger,MIPS64: 阶段2: 交互式争议（二分法）
        loop 争议轮次（直到达到分割深度）
            alt 挑战者回合
                Challenger->>Game: attack(parentIndex, claim, bond)
                Game->>Game: claimData.push(newClaim)
                Game-->>Challenger: Move 事件
            else 防御者回合
                Sequencer->>Game: defend(parentIndex, claim, bond)
                Game->>Game: claimData.push(newClaim)
                Game-->>Sequencer: Move 事件
            end
        end

        Note over Challenger,MIPS64: 阶段3: 单步执行证明（在分割深度）
        Challenger->>Game: step(claimIndex, isAttack, stateData, proof)
        Game->>MIPS64: step(state, instruction, proof)
        MIPS64->>MIPS64: 执行MIPS64指令
        MIPS64-->>Game: 返回新状态
        alt 状态转换无效
            Game->>Game: status = CHALLENGER_WINS
            Game->>Game: 分配保证金给挑战者
            Game->>AnchorRegistry: 更新状态（游戏被尊重）
            Note over Portal: 阻止基于此无效状态根的提款
        else 状态转换有效
            Game->>Game: status = DEFENDER_WINS
            Game->>Game: 分配保证金给防御者
            Note over Portal: 允许基于此状态根的提款
        end

        Note over Challenger,MIPS64: 阶段4: 解决争议游戏
        Game->>Game: resolve()
        Game-->>Challenger: Resolved 事件
    end

    Note over User,MIPS64: ========== 流程关联说明 ==========
    Note over Sequencer,AnchorRegistry: Sequencer定期提交L2状态根到AnchorStateRegistry
    Note over Portal,Game: 提款证明需要基于有效的DisputeGame
    Note over Game,Portal: 如果争议游戏判定状态根无效，相关提款将被阻止
```

## 1. 存款流程（Deposit）

### ETH 存款流程

```mermaid
sequenceDiagram
    participant User as 用户
    participant L1Bridge as L1StandardBridge
    participant L1Messenger as L1CrossDomainMessenger
    participant Portal as OptimismPortal2
    participant RollupNode as Rollup节点
    participant L2Messenger as L2CrossDomainMessenger
    participant L2Bridge as L2StandardBridge

    User->>L1Bridge: depositETH(amount, gasLimit, extraData)
    Note over L1Bridge: 检查暂停状态
    L1Bridge->>L1Messenger: sendMessage{value: amount}(L2Bridge, finalizeBridgeETH)
    Note over L1Messenger: 记录消息哈希
    L1Messenger->>Portal: depositTransaction(to, value, gasLimit, false, data)
    Note over Portal: 如果启用ETHLockbox，锁定ETH
    Portal-->>RollupNode: 发出 TransactionDeposited 事件
    Note over RollupNode: 监听事件，构建L2区块
    RollupNode->>L2Messenger: 执行存款交易
    L2Messenger->>L2Bridge: finalizeBridgeETH(from, to, amount, extraData)
    Note over L2Bridge: 验证消息来源
    L2Bridge->>User: 转账 ETH (SafeCall.call)
    L2Bridge-->>User: 发出 ETHBridgeFinalized 事件
```

### ERC20 存款流程

```mermaid
sequenceDiagram
    participant User as 用户
    participant L1Token as L1 ERC20 Token
    participant L1Bridge as L1StandardBridge
    participant L1Messenger as L1CrossDomainMessenger
    participant Portal as OptimismPortal2
    participant RollupNode as Rollup节点
    participant L2Messenger as L2CrossDomainMessenger
    participant L2Bridge as L2StandardBridge
    participant L2Token as L2 ERC20 Token

    User->>L1Bridge: depositERC20(l1Token, l2Token, amount, gasLimit, extraData)
    Note over L1Bridge: 检查暂停状态
    alt L1原生代币
        L1Bridge->>L1Token: safeTransferFrom(user, bridge, amount)
        Note over L1Bridge: deposits[l1Token][l2Token] += amount
    else L2原生代币(OptimismMintableERC20)
        L1Bridge->>L1Token: burn(from, amount)
    end
    L1Bridge->>L1Messenger: sendMessage(L2Bridge, finalizeBridgeERC20)
    L1Messenger->>Portal: depositTransaction(to, 0, gasLimit, false, data)
    Portal-->>RollupNode: 发出 TransactionDeposited 事件
    RollupNode->>L2Messenger: 执行存款交易
    L2Messenger->>L2Bridge: finalizeBridgeERC20(l2Token, l1Token, from, to, amount, extraData)
    Note over L2Bridge: 验证消息来源
    alt L1原生代币
        L2Bridge->>L2Token: mint(to, amount)
    else L2原生代币
        L2Bridge->>L2Token: safeTransfer(to, amount)
    end
    L2Bridge-->>User: 发出 ERC20BridgeFinalized 事件
```

## 2. 提款流程（Withdrawal）

### 提款完整流程（包含证明和最终确认）

```mermaid
sequenceDiagram
    participant User as 用户
    participant L2Bridge as L2StandardBridge
    participant L2Messenger as L2CrossDomainMessenger
    participant L2ToL1Passer as L2ToL1MessagePasser
    participant RollupNode as Rollup节点
    participant Prover as 证明者
    participant Portal as OptimismPortal2
    participant DisputeGame as DisputeGame
    participant L1Bridge as L1StandardBridge

    Note over User,L1Bridge: 阶段1: 在L2发起提款
    User->>L2Bridge: withdraw(l2Token, amount, gasLimit, extraData)
    alt ETH提款
        L2Bridge->>L2Messenger: sendMessage{value: amount}(L1Bridge, finalizeBridgeETH)
    else ERC20提款
        L2Bridge->>L2Token: burn(from, amount) 或 transfer
        L2Bridge->>L2Messenger: sendMessage(L1Bridge, finalizeBridgeERC20)
    end
    L2Messenger->>L2ToL1Passer: initiateWithdrawal(target, gasLimit, data)
    Note over L2ToL1Passer: sentMessages[withdrawalHash] = true
    L2ToL1Passer-->>RollupNode: 发出 MessagePassed 事件
    Note over RollupNode: 将L2ToL1MessagePasser的存储根包含在输出根中

    Note over User,L1Bridge: 阶段2: 在L1证明提款（等待挑战期后）
    RollupNode->>DisputeGame: 创建DisputeGame（如果状态根有效）
    Prover->>Portal: proveWithdrawalTransaction(tx, disputeGameIndex, outputRootProof, withdrawalProof)
    Note over Portal: 验证Merkle证明<br/>验证输出根证明<br/>检查DisputeGame状态
    Portal->>Portal: provenWithdrawals[withdrawalHash][prover] = ProvenWithdrawal
    Portal-->>Prover: 发出 WithdrawalProven 事件
    Note over Portal: 等待 PROOF_MATURITY_DELAY_SECONDS

    Note over User,L1Bridge: 阶段3: 最终确认提款
    User->>Portal: finalizeWithdrawalTransaction(tx, proofSubmitter)
    Note over Portal: 检查证明成熟度<br/>检查DisputeGame有效性<br/>检查是否已最终确认
    Portal->>Portal: finalizedWithdrawals[withdrawalHash] = true
    alt 使用ETHLockbox
        Portal->>ETHLockbox: unlockETH(amount)
    end
    Portal->>L1Bridge: finalizeBridgeETH/ERC20 (通过SafeCall)
    L1Bridge->>User: 转账资产
    Portal-->>User: 发出 WithdrawalFinalized 事件
```

## 3. 争议流程（Dispute）

### 争议游戏完整流程

```mermaid
sequenceDiagram
    participant Challenger as 挑战者
    participant Factory as DisputeGameFactory
    participant Game as FaultDisputeGame
    participant Defender as 防御者(Sequencer)
    participant AnchorRegistry as AnchorStateRegistry
    participant Portal as OptimismPortal2
    participant MIPS64 as MIPS64虚拟机
    participant PreimageOracle as PreimageOracle

    Note over Challenger,PreimageOracle: 阶段1: 创建争议游戏
    Challenger->>Factory: create(gameType, rootClaim, extraData)
    Note over Factory: 检查游戏类型实现<br/>检查初始化保证金
    Factory->>Game: initialize() {value: initBond}
    Note over Game: 从AnchorStateRegistry获取锚定根<br/>验证rootClaim有效性<br/>存入保证金到WETH
    Game->>Game: claimData.push(rootClaim)
    Game->>AnchorRegistry: 记录游戏创建
    Game-->>Challenger: 发出 GameCreated 事件

    Note over Challenger,PreimageOracle: 阶段2: 交互式争议（二分法）
    loop 争议轮次（直到达到分割深度）
        alt 挑战者回合
            Challenger->>Game: attack(parentIndex, claim, bond)
            Note over Game: 验证父声明存在<br/>验证位置有效性<br/>存入保证金
            Game->>Game: claimData.push(newClaim)
            Game-->>Challenger: 发出 Move 事件
        else 防御者回合
            Defender->>Game: defend(parentIndex, claim, bond)
            Note over Game: 验证父声明存在<br/>验证位置有效性<br/>存入保证金
            Game->>Game: claimData.push(newClaim)
            Game-->>Defender: 发出 Move 事件
        end
    end

    Note over Challenger,PreimageOracle: 阶段3: 单步执行证明（在分割深度）
    Challenger->>Game: step(claimIndex, isAttack, stateData, proof)
    Note over Game: 验证位置在分割深度<br/>验证状态转换正确性
    Game->>MIPS64: step(state, instruction, proof)
    MIPS64->>PreimageOracle: 获取预映像数据
    PreimageOracle-->>MIPS64: 返回数据
    MIPS64->>MIPS64: 执行MIPS64指令
    MIPS64-->>Game: 返回新状态
    Game->>Game: 验证状态转换
    alt 状态转换无效
        Game->>Game: 标记挑战者获胜
        Game->>Game: 分配保证金给挑战者
    else 状态转换有效
        Game->>Game: 标记防御者获胜
        Game->>Game: 分配保证金给防御者
    end

    Note over Challenger,PreimageOracle: 阶段4: 解决争议游戏
    Game->>Game: resolve()
    Note over Game: 遍历子游戏树<br/>确定最终获胜者
    alt 挑战者获胜
        Game->>Game: status = CHALLENGER_WINS
        Game->>AnchorRegistry: 更新状态（如果游戏被尊重）
        Note over Portal: 阻止基于此状态根的提款
    else 防御者获胜
        Game->>Game: status = DEFENDER_WINS
        Note over Portal: 允许基于此状态根的提款
    end
    Game-->>Challenger: 发出 Resolved 事件
```

## 关键合约交互说明

### 存款流程关键点

1. **L1 → L2**: 通过 `OptimismPortal2.depositTransaction` 发出事件，Rollup节点监听并构建L2交易
2. **消息传递**: 使用 `CrossDomainMessenger` 确保消息的可信传递
3. **代币处理**:
   - L1原生代币：在L1锁定，在L2铸造
   - L2原生代币：在L1销毁，在L2转移

### 提款流程关键点

1. **三阶段流程**:
   - 阶段1: L2发起提款，记录在 `L2ToL1MessagePasser`
   - 阶段2: 在L1证明提款（需要Merkle证明和有效的DisputeGame）
   - 阶段3: 等待成熟期后最终确认
2. **证明要求**: 需要提供输出根证明和Merkle包含证明
3. **安全机制**: `PROOF_MATURITY_DELAY_SECONDS` 防止重放攻击

### 争议流程关键点

1. **交互式二分法**: 通过不断缩小争议范围，最终在单步执行上验证
2. **保证金机制**: 双方都需要存入保证金，失败方损失保证金
3. **MIPS64执行**: 在分割深度使用MIPS64虚拟机执行单步证明
4. **状态根验证**: 通过 `AnchorStateRegistry` 管理有效的状态根
